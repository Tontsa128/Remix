# Elovio — TTS provider evaluation

**Review date:** 2026-11-07  
**Status:** preliminary technical evaluation; no provider has been selected or integrated.

## Decision summary

Google Cloud Text-to-Speech is the first candidate to take into a controlled proof-of-quality evaluation for the initial locales. Its published voice catalogue explicitly lists both male- and female-labelled voices for Finnish (fi-FI), Spanish (Spain, es-ES), and English (at least en-US and en-GB). This is an important match for Elovio's required voice preference.

This is **not** a production provider decision. Voice catalogue availability alone does not establish pronunciation quality, acceptable latency, pricing, GDPR suitability, retention behavior, or end-to-end support for live interpretation. Do not enable speech features or mark TTS as supported based on this review alone.

## Published voice coverage

The Google Cloud voice catalogue lists:

| Locale | Male voice examples | Female voice examples | Published availability |
|---|---|---|---|
| Finnish (fi-FI) | Chirp 3 HD: Achird, Charon, Fenrir | Chirp 3 HD: Achernar, Aoede, Kore | Both genders listed |
| Spanish (Spain, es-ES) | Chirp 3 HD: Achird, Algenib, Charon | Chirp 3 HD: Achernar, Aoede, Kore | Both genders listed |
| English (US, en-US) | Chirp 3 HD: Achird, Charon, Fenrir | Chirp 3 HD: Achernar, Aoede, Kore | Both genders listed |
| English (UK, en-GB) | Standard/Studio/WaveNet voices include male options | Standard/Studio/WaveNet voices include female options | Both genders listed |

Voice IDs and availability must be obtained from the live provider catalogue rather than copied permanently from this document. The provider documents a ListVoices API that returns voice name, supported language codes, and SSML voice gender.

## Important product and technical constraints

- Store the user's preference as `male` or `female`, independently of all language preferences.
- Resolve that preference against the actual voice catalogue for the requested BCP 47 locale at runtime.
- Persist the provider voice ID only as a resolved cache/selection; keep the preference itself provider-independent.
- Never infer gender from a voice name. Use the provider's returned gender metadata and validate the result before synthesis.
- If the selected locale has no voice matching the requested preference, explain the limitation and request a new choice. Never silently substitute.
- Provide a genuine preview generated by the same provider and selected voice that will be used in lessons.
- Keep provider credentials on a trusted backend. Never ship Google service credentials or privileged tokens in the Expo application.
- The provider's documentation says Chirp 3 HD supports low-latency text streaming, but does not support SSML input, speaking-rate controls, or pitch/audio parameters. Evaluate whether this is sufficient for language-learning pacing, sentence segmentation, and pronunciation teaching. If not, compare a compatible Neural2/WaveNet tier.
- The catalogue documentation says Chirp 3 HD is available through global, EU, and US endpoints but is out of scope for regionalization and data residency. An EU endpoint must not be treated as proof that all processing or storage stays in the EU. Privacy/legal review is required.
- TTS is only speech output. This review does not establish ASR, translation, language identification, or full duplex/live interpretation capability.

## Required proof-of-quality before selection

1. Generate the same reviewed Finnish, Spain-Spanish, and English learning samples with at least one male and one female voice per locale.
2. Have fluent speakers assess pronunciation, prosody, intelligibility, regional appropriateness, and naturalness. For Spanish, explicitly verify Spain Spanish rather than Latin American pronunciation.
3. Measure real request latency, streamed time-to-first-audio where applicable, playback reliability, and audio quality on physical Android and iOS devices.
4. Test short phrases, long explanations, numbers, dates, names, questions, punctuation, and sentence-level pauses.
5. Review current pricing against realistic lesson and live-interpretation usage; calculate per-user cost and gross-margin impact.
6. Review DPA, subprocessors, retention, training/use of submitted text, deletion, data residency, and applicable GDPR obligations.
7. Test provider failures, rate limits, timeouts, cancellation, interruption, and voice-catalogue changes.
8. Record evidence and test results before enabling any locale in the product capability registry.

## Current conclusion

**Candidate for evaluation:** Google Cloud Text-to-Speech.  
**Production selection:** pending.  
**Implementation status:** none. No TTS request, audio playback, voice preview, or listening exercise is implemented by this evaluation.
